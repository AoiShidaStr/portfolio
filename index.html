Rivages des Morts

Un action-RPG de donjon en vue isométrique, jouable dans le navigateur, en coop en ligne jusqu'à trois ou en duel. Tu incarnes une âme échouée au Yomi, l'au-delà japonais, face à ses yokai et à ses dieux. J'en porte le game design, l'univers et le développement, du moteur de combat au serveur.

Page complète du jeu →

Moteur de jeu temps réel

La logique du combat ne connaît ni le rendu ni le DOM : le même monde tourne chez l'hôte, sur le serveur ou dans un rejeu.

  • Rendu Babylon.js, pixel art, résolution adaptative à la carte graphique
  • 3 donjons + un donjon sans fin à paliers, 3 boss à phases
  • 5 classes, compétences, builds, équipement et forge

Multijoueur en ligne

Trois architectures réseau, chacune choisie pour son usage.

  • Coop pair à pair (WebRTC) avec prédiction locale de l'invité
  • Duel à rollback : on devine les commandes adverses, on rejoue si on s'est trompé
  • Serveur Node.js : comptes, amis, chat, coop sans hôte (WebSocket, Docker, Caddy)

Données et outillage

Le contenu se décrit, il ne se code pas : ajouter un ennemi ou une quête ne touche pas au moteur.

  • 24 fichiers JSON : ennemis, vagues, objets, quêtes, dialogues
  • 32 outils Node.js (~15 000 lignes) : sprites, équilibrage, simulation de DPS, éditeur
  • Bots qui jouent la coop pour tester sans réseau

Produit et livraison

Un jeu en ligne, utilisé, qui évolue chaque semaine sans casser les sauvegardes.

  • CI GitHub Actions : chaque PR vérifiée, chaque fusion déployée
  • Notes de version lisibles en jeu, alerte quand une version sort
  • Sauvegardes exportables, options d'accessibilité (secousses, graphismes allégés)
src/net/rollback.ts · extraitduel en ligne

Pendant un duel, les deux navigateurs simulent le même combat, avec la même graine. Seules les commandes transitent : sept entiers par pas, dont neuf boutons tassés dans un champ de bits.

/** Une commande en sept nombres : direction (au millième),
 *  visée et sol visé (au centimètre), boutons. */
type Packed = number[];

function pack(frame: InputFrame): Packed {
  let flags = 0;
  BUTTONS.forEach((key, i) => {
    if (frame[key]) flags |= 1 << i;
  });
  const r = (x: number, k: number) => Math.round(x * k);
  return [r(frame.move.x, 1000), r(frame.move.z, 1000),
          r(frame.aim.x, 100), r(frame.aim.z, 100),
          r(frame.aimGround.x, 100), r(frame.aimGround.z, 100),
          flags];
}

Méthode

Comment je travaille

La même discipline sur un jeu personnel et chez un client : on écrit ce qu'on construit, on le découpe, on le vérifie, on le livre.

Cadrer

Un game design document pour le jeu, un cahier des charges vérifié pour un client : ce qu'on construit est écrit avant d'être codé.

Découper

Une branche et une pull request par changement : 73 fusionnées sur Rivages des Morts, avec un historique qui se relit.

Vérifier

Typage strict, vérification automatique de chaque PR, outils d'équilibrage, bots de test, et chaque version testée en jouant.

Livrer

Déploiement continu à chaque fusion, versions numérotées et notes de version écrites pour les joueurs.

L'IA, utilisée comme un outil de pro

Je développe avec Claude Code comme assistant de programmation, et je crée mes propres skills pour lui (voir le skill Cahier des charges plus bas). L'architecture, le game design et le choix de ce qui entre dans le code restent les miens : chaque changement passe par une pull request que je relis et teste avant de la fusionner. C'est ce qui me permet de livrer vite sans perdre la maîtrise de la base de code.
