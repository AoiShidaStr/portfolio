Rivages des Morts

Un action-RPG de donjon en pixel art isométrique, jouable dans le navigateur, en coop en ligne jusqu'à trois ou en duel. J'en porte le game design, l'univers et tout le développement.

Game design

Ce qu'on y joue, et pourquoi c'est ainsi.

Jouable aujourd'hui

  • L'île du Yomi : PNJ, quêtes, forge, boutiques, et un cycle jour et nuit.
  • Trois donjons et leurs boss : la Jorōgumo, Izanami, et le gardien errant du Mont Fujikasane.
  • Le Yomi sans fond : une descente infinie par paliers, avec sceaux, pactes et records.
  • Cinq classes et leurs voies, compétences, builds qui se changent d'une touche.
  • Inventaire en grille, forge, gravures et durabilité, échanges entre joueurs.
  • Coop en ligne à trois, et un duel en deux manches dans une arène qui rétrécit.

Décisions de conception

  • Une règle d'univers qui produit du gameplay. « On existe tant qu'on se souvient de nous » explique l'effondrement, les ennemis, la rareté des reliques et le ton des quêtes.
  • Lisibilité avant tout. Chaque attaque s'annonce au sol, chaque ennemi a un contre, et le bord de chaque arène se voit.
  • Le ressenti d'abord. Pause d'impact, recul, sons choisis un par un : un coup doit se sentir.
  • Corriger vite. La 0.25.0 jetait les joueurs trop loin dans le Yomi : corrigé le jour même en 0.25.1.

Savoir jeter

  • En version 0.21, j'ai abandonné tout le style peint pour passer au pixel art.
  • Les planches peintes dérivaient d'une image à l'autre (visage, taille, tenue) et restaient floues à la taille du jeu.
  • Le pixel art garde le même héros du premier au dernier pas, se retouche case par case et pèse moins lourd.
  • Un choix coûteux à court terme, fait parce qu'il servait le joueur.

Sous le capot

Une architecture pensée pour durer.

TypeScript strict, Babylon.js et Vite. La logique du combat ne dépend ni du rendu ni du réseau : le même monde tourne chez l'hôte, sur le serveur ou dans le rejeu d'un duel.

Coop pair à pair

WebRTC (Trystero), sans serveur de jeu : l'hôte fait tourner le combat.

  • Un canal fiable pour les événements, un canal rapide sans renvoi pour les positions
  • Prédiction locale : l'invité ne sent pas le ping quand il marche

Duel à rollback

Les deux navigateurs simulent le même combat, à pas fixe, avec la même graine.

  • Les commandes adverses sont devinées, puis le monde est rejoué si on s'est trompé
  • Une empreinte du monde comparée toutes les deux secondes détecte les divergences

Serveur dédié

Un serveur Node.js optionnel, livré en conteneur.

  • Comptes, amis, groupes et chat par WebSocket
  • Coop sans hôte : le combat tourne sur le serveur
  • Docker Compose, Caddy en frontal

Outillage maison

32 outils Node.js, lancés par des scripts npm.

  • Détourage et découpe de sprites, icônes, effets visuels
  • Simulateurs d'équilibrage et de DPS, un éditeur de zones
  • Bots qui jouent la coop pour tester sans réseau
src/net/rollback.ts · extraitduel en ligne

Seules les commandes transitent pendant un duel : sept entiers par pas. Direction et visée sont arrondies, neuf boutons tiennent dans un champ de bits.

/** Une commande en sept nombres : direction (au millième),
 *  visée et sol visé (au centimètre), boutons. */
type Packed = number[];

function pack(frame: InputFrame): Packed {
  let flags = 0;
  BUTTONS.forEach((key, i) => {
    if (frame[key]) flags |= 1 << i;
  });
  const r = (x: number, k: number) => Math.round(x * k);
  return [r(frame.move.x, 1000), r(frame.move.z, 1000),
          r(frame.aim.x, 100), r(frame.aim.z, 100),
          r(frame.aimGround.x, 100), r(frame.aimGround.z, 100),
          flags];
}

Fabrication

Comment je le fabrique

Un flux de travail de studio

  • Un game design document tenu à jour, qui décide de ce qui entre dans le jeu.
  • Une branche et une pull request par changement, vérifiée automatiquement (typage, build).
  • Chaque PR testée en jouant avant fusion, puis déployée sur GitHub Pages par GitHub Actions.
  • Des notes de version écrites pour les joueurs, lisibles depuis l'écran titre.

L'IA, à sa place

  • Je développe avec Claude Code comme assistant de programmation.
  • Le game design, l'univers, l'équilibrage, l'architecture et le choix de ce qui entre dans le jeu restent les miens.
  • Les graphismes sont produits avec des outils d'IA, puis détourés, corrigés et intégrés par mes propres scripts : je ne me présente pas comme graphiste.
  • C'est ce qui permet à une seule personne de tenir ce rythme sans perdre la maîtrise du code.
Ce projet m'apprend à trancher : garder un prototype jouable à chaque étape plutôt qu'accumuler des systèmes, et juger une mécanique sur ce qu'elle fait ressentir en partie, pas sur le papier. La suite est écrite dans le game design document : d'autres îles (les rives de l'Hadès, la Duat, le Helheim), chacune avec sa mythologie et son dieu en boss final.
